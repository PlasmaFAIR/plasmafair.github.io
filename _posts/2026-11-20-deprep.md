At the beginning of the project, the code was written well but the directory structure needed to changes to allow for
easy installation using [uv][uv]. This allowed also included adding a uv.lock file to ensure reproducibility by others
going forward, and minimum dependency versions to ensure the code stays up-to-date with [SPEC0][SPEC0]. The README was
overhauled to add clear instructions for users, as well as formatting to improve readability.

As with any project, the ability to test the software was critical. A large regression test was implemented early on
using [snaptol][snaptol] to ensure changes that were being made, were not introducing any changes to the output
results. This also helped in revamping the suite itself by adding a good number of unit tests to target smaller
functions. The tests ranged from numerical checks of equations, to analysing data reading and setup. To extend this,
and to ensure smooth collaboration in the future, workflows were added to allow the test suite actions to run on pull
requests. This is known as continuous integration, and allows the code to be ran on a range of Python versions and
operating systems on the host version control system with ease. A set of linting rules were introduced using the
[ruff][ruff] software, to remove bad code smells and improve formatting. These also had their own workflow to enforce
this on pull requests.

The ability to produce local documentation was added using [sphinx][sphinx], with the potential to upload this later to
[readthedocs][readthedocs]. A host of other small changes were also made, such as using the `gzip` module instead of
shell commands, improvements of missing input file errors messages, the use of the `argparse` module and more. Some
bugs were identified in the code with solutions advised.

As always, this project required me to use a collection of tools and skills I've learnt over my time as part of
PlasmaFAIR, and I look forward to more projects like this in the future!
